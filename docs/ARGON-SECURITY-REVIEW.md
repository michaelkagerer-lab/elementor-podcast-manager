## Compatibility and security boundaries

- Secure remote feed requests now require direct PHP cURL. An HTTP proxy, non-cURL/custom transport, or IPv6-only destination fails with an actionable error. Existing stored episodes are not rewritten. Confirm hosting compatibility before production deployment.
- Rate limits and elapsed-time checks reduce abuse; public analytics cannot prove human listening. Distributed clients can still fabricate plausible sessions. These figures remain website-player telemetry, not billing-grade or certified audience measurement. Shared rate buckets can also throttle unrelated clients under heavy abuse.
- Core/plugin trusted PHP filters can explicitly permit private destinations (the disposable media suite does this for one local port). Plugins with server-side code execution remain inside the trusted boundary.
- Tests use local SQLite, Chromium and Elementor Free. Production database/proxy configuration, Elementor Pro templates, Safari and real consent-provider configuration require separate acceptance. No production credentials or private settings were copied.
